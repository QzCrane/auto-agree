# Auto Agree v1.1.0 — Reconstructed Historical Record

> Evidence class: **reconstructed from the original v1.1 commit** `56c695443cc9099ed35de9c9f1be2cfe0d492c6f`, plus the project’s recorded real-world TRAE classless-control confirmation.
>
> v1.1 did not have a standalone contemporaneous verification report. This document separates committed changes from retrospective conclusions and does not invent missing benchmark data.

## 1. Why v1.1 existed

v1 exposed two important real-world weaknesses:

1. a website could display an agreement box without any reliable checkbox class/role/input semantics, so checkbox-first discovery never found it;
2. a successful click on an unknown custom component could be followed by a blind retry that toggled it back off because v1 did not recognize the component’s checked-state representation.

v1.1 targeted both failures directly rather than merely adding more checkbox selectors.

## 2. Stronger legal/auth semantics

The positive agreement model was strengthened:

- Chinese read/agree distance windows were widened;
- User/Service/Privacy Agreement evidence received stronger weights;
- TRAE agreement wording was explicitly recognized in the vocabulary used during that debugging cycle;
- authentication context added `立即注册` and broader surrounding context;
- search depth for semantic containers and authentication context increased.

The point was not simply “more keywords”: v1.1 increased the chance that a fragmented/custom agreement row would be recognized strongly enough to enter reverse discovery.

## 3. Checked-state model expansion

v1.1 substantially expanded the states considered observably checked.

It added explicit handling for checked variants used by common UI libraries, including patterns such as:

- Semi checked classes;
- Ant wrapper/input checked classes;
- Arco checked classes;
- Naive UI checked classes;
- Vant checked icon classes;
- generic `is-checked`, `checkbox-checked`, `checkbox_checked`, and `checkbox--checked` forms.

It also introduced `stateObservable()` to distinguish:

- controls whose checked state can be read reliably;
- controls whose state representation is unknown.

This was a structural correctness improvement because retry policy could now depend on observability rather than assumption.

## 4. Safe retry semantics

v1 blindly retried once if `checked()` still returned false.

v1.1 changed the rule to:

```text
known observable state
    ↓
first click
    ↓
still definitely unchecked?
    ↓
limited retry allowed

unknown state
    ↓
click once
    ↓
no blind second toggle
```

This directly closed the “checked → misread → clicked again → unchecked” failure class.

The retry delay was also changed from 500 ms to 650 ms for known observable components, but the important improvement was **conditional retry authority**, not the exact delay.

## 5. Reverse discovery: text → control

This was the defining architectural change of v1.1.

Instead of only:

```text
known checkbox
→ inspect nearby text
```

v1.1 added the inverse path:

```text
strong agreement text
→ identify the smallest useful text anchor
→ expand to the agreement row
→ search nearby for a plausible visual control
→ activate only after semantic and geometric checks
```

The implementation introduced concepts including:

- `ANCHOR_SELECTOR` over labels/paragraphs/spans/divs/sections/list items;
- `smallestAgreementElement()` to find a compact agreement-text anchor rather than using a huge ancestor;
- `agreementRow()` to expand from the text anchor to the smallest useful enclosing row;
- `smallVisualControl()` to find a small, approximately square nearby element when normal checkbox semantics were absent.

This is the mechanism family that allowed TRAE-style classless agreement UI to be handled.

## 6. Geometry as a fallback, not primary authority

The visual-control fallback scored candidates using properties such as:

- small dimensions;
- roughly square aspect ratio;
- vertical alignment with the agreement text;
- class/role hints such as check/tick/agree/select;
- checkbox role/native checkbox evidence when present.

This meant geometry could bridge a missing semantic control API, but only after strong agreement semantics had already identified the row.

Later versions kept this principle while moving geometry even further down the fallback chain to reduce layout cost and false positives.

## 7. Broader framework target resolution

The click-target resolver was widened beyond only native input and role checkbox:

- native input remained preferred;
- ARIA checkbox remained preferred;
- known checkbox wrappers/components could become the target;
- generic row fallback still existed when stronger control evidence was unavailable.

The later removal of whole-row clicking in v2/v3-era hardening was a response to the residual risk of that final fallback.

## 8. Scan scheduling and duplicate control

v1.1 introduced more explicit scan coordination, including state used to avoid repeatedly scheduling the same broad scan work and a `WeakSet` for agreement anchors already attempted.

This was an intermediate step toward the later incremental dirty-subtree queues and time-budgeted walkers.

## 9. Real-world TRAE significance

The project history records v1.1 as the point where the classless-control path was confirmed against the real TRAE login agreement flow.

The important lesson was broader than one website:

> DOM class names and checkbox roles are implementation details; the automation must be able to begin from legal semantics and reconstruct the likely control relationship when conventional semantics are missing.

That lesson survived into all later versions.

## 10. Remaining limitations after v1.1

These are retrospective limitations demonstrated by subsequent refactors.

### 10.1 Still a single always-loaded engine

Every matching page/frame still ran the full implementation whether or not the page contained relevant UI.

### 10.2 Still too much broad DOM work

The version still relied on large subtree scans and textual ancestor inspection. It did not yet have the bounded incremental walk architecture introduced in v2.

### 10.3 Layout reads remained common

Classless reverse discovery increased the importance of geometry and visibility checks. At this stage those reads were not yet sufficiently isolated from ordinary hot paths.

### 10.4 Closed Shadow DOM remained outside the original discovery model

v1.1 did not yet use `chrome.dom.openOrClosedShadowRoot()` as the systematic closed-root mechanism later introduced in v2.

### 10.5 Risk taxonomy was still mostly a negative-word list

The version could exclude many dangerous/optional controls, but it did not yet model factual attestation separately as comprehensively as v2, nor the later behavior-consequence severity lattice.

### 10.6 Whole-row fallback remained possible

When no precise target could be determined, clicking a containing agreement row could trigger framework behavior other than checking the box. This was later eliminated in favor of precise hit-target resolution.

## 11. Historical significance

v1.1 changed Auto Agree from a conventional “smart checkbox finder” into a bidirectional UI inference system:

```text
control → semantics
and
semantics → control
```

It also established the durable safety rule:

> **Unknown toggle state is not evidence that the first click failed.**

Those two ideas are still fundamental in v7.
