# Auto Agree v9.0.0 — Verification Report

Generated: 2026-08-08

## Scope

v9 is an invariant-recovery release derived by reconciling the complete v1→v8 engineering record against the live v8 runtime. The audit found both ordinary runtime regressions and a previously unmodeled Manifest V3 update property: an old extension isolated world can remain observable **and executable** after the new extension generation has installed into the same, non-reloaded page.

v9 hardens two independent boundaries:

1. **current-generation correctness** — UNKNOWN one-shot state, tri-state refusal, seed ownership, dependency-safe initialization and sender-bound profile identity;
2. **cross-generation click authority** — a high-priority handover firewall that prevents a stale Engine world from clicking under superseded semantics without breaking genuine user-caused custom-control delegation.

## Recovered current-generation invariants

- UNKNOWN-state classless controls are one-shot for the lifetime of the unresolved DOM element; cooldown expiry alone can never authorize a second toggle.
- If `HTMLElement.click()` itself throws before dispatch, the UNKNOWN one-shot is not consumed.
- Native `indeterminate`, `aria-checked="mixed"`, and data `indeterminate` / `mixed` states are tri-state or aggregate ambiguity and are never auto-confirmed.
- Gate→Engine seed handoff is consumed from the global exactly once but remains weakly readable by both Shadow bootstrap and scoped Engine bootstrap.
- Gate/Engine sentinels are published only after dependencies validate, so partial/out-of-order injection cannot poison later retries.
- Engine activation injects the current `semantic-core.js`, `risk-core.js`, and `engine.js` dependency closure.
- Profile storage origin is derived from Chrome `MessageSender.origin` / `url`; content-provided origin text is neither sent nor trusted. Profile operations fail closed without a usable HTTP(S) sender origin.

## Cross-generation handover firewall

### Discovery: sentinels were not authority

The first expanded v8→v9 update test disproved the assumption that an already-active v8 Engine would remain the only Engine world after update. Chrome preserved the non-reloaded page and exposed both v8 and v9 isolated-world Engine sentinels.

A stronger behavioral discriminator then inserted `aria-checked="mixed"`. v8 treated `mixed` as unchecked; v9 refuses it as tri-state ambiguity. The surviving v8 world produced **2 clicks** after update: first attempt plus verifier retry.

Therefore the old world was not merely a stale global. It remained executable and still held click authority.

### Direct current-Engine authorization

Update rehydration now injects `handover-guard.js` **before** `bootstrap.js` into accessible surviving frames at elevated scheduler priority.

The guard:

- lets trusted user events pass;
- inspects synthetic/untrusted clicks;
- bounds local semantic inspection by explicit node/character budgets;
- recognizes agreement-like click surfaces, including local legal/control evidence and accessible Shadow content;
- blocks agreement-like synthetic clicks unless the current Engine synchronously issued a one-shot authorization for that DOM target/ancestor chain.

Current v9 Engine authorizes both first-attempt and verifier-retry `.click()` calls immediately before dispatch. A stale v8 Engine cannot access the new isolated world's WeakSet authorization state. If current authorization produces no click event, the unused direct token expires at the next microtask checkpoint.

### Event-propagation causal delegation

A second adversarial test found a compatibility hazard in the firewall itself. Many custom controls implement:

```text
trusted click on visible wrapper
→ MAIN-world component handler
→ input.click()
→ synthetic descendant click
```

The nested click is synthetic even though it is causally user-owned.

A microtask-only local exception was implemented and **failed in real Chrome**: the extension isolated world and MAIN world can cross a microtask checkpoint during one DOM event, so the local exception disappeared before the page's wrapper handler ran.

The accepted model is event-scoped instead:

1. capture phase identifies only a small control/wrapper root;
2. one descendant causal lease exists for the same DOM event propagation;
3. page code may synchronously delegate one descendant synthetic click;
4. bubble phase revokes the lease before later MutationObserver work;
5. broad `form`, `dialog`, `section`, page/document containers are not lease roots;
6. no timer-based authorization window survives into a later task.

The same local causal mechanism is available when a current-authorized Engine click enters page component code and synchronously delegates to a descendant control.

## Regression gates

### Tri-state refusal

Real unpacked Chrome covers three independent ambiguous-state representations:

- ARIA `aria-checked="mixed"`;
- custom `data-state="indeterminate"`;
- native checkbox `indeterminate === true`.

All three must remain untouched with exact click count zero.

### UNKNOWN one-shot

A classless visual control with no observable checked contract is allowed one activation. The fixture waits beyond the normal 2.2-second cooldown, mutates legal text to trigger fresh semantic work, and requires the click count to remain exactly one.

### v8→v9 update transition

The update gate keeps real pages alive across the same unpacked-extension replacement and proves:

1. a dormant v8 Probe can hand through the v9 Worker into a v9 Engine;
2. an already-active v8 Engine world may coexist with a current v9 Engine world;
3. the v9 handover guard is physically present before post-update behavior is exercised;
4. one current routine agreement receives exactly one authorized click;
5. the stale-v8 mixed-state discriminator receives exactly zero clicks;
6. a genuine trusted browser click on a small custom Terms wrapper may still synchronously delegate exactly one page-owned synthetic descendant click;
7. main-world markers survive, proving the pages themselves did not reload.

### Deterministic contracts

The dependency-free core pins:

- Manifest V3 permissions and isolated-world/frame configuration;
- no production network client, eval/dynamic Function, polling interval, debugger path or whole-page wildcard scan;
- 10,020 semantic severity/property assertions;
- Worker exact-document injection, document lifecycle rejection, bounded scheduling, fairness, aging and stale eviction;
- service-worker restart and persisted profile/update-rehydration state;
- sender-bound profile identity and fail-closed missing-origin behavior;
- Engine current-version dependency closure;
- update injection ordering (`handover-guard.js` before `bootstrap.js`);
- direct handover authorization and microtask expiry;
- event-propagation causal delegation and explicit absence of timer-based authorization leases.

The local exception was rebuilt around event propagation rather than microtask lifetime.

## Exact-head verification record policy

The repository report records the latest **code-bearing** verified candidate. Embedding the subsequent final CI run ID/SHA into this file would itself create a new commit/head and require another CI run, producing an infinite evidence-self-reference loop.

## Remaining boundaries

The v8→v9 handover cannot be retroactively atomic. v8 shipped no revocable resident generation lease, so there is a finite interval between extension replacement and successful v9 guard injection into a surviving frame. Eliminating that historical gap entirely would require prior-generation cooperation or page navigation/reload.

The firewall is scoped to Auto Agree's consequential stale authority—agreement-like synthetic clicks. It is not a generic sandbox for arbitrary historical extension code side effects.

The regression corpus is structural rather than internet-exhaustive. Chrome-owned UI, trusted-physical-input requirements, pure Canvas/WebGL interaction without usable DOM/accessibility semantics, and semantics intentionally hidden outside finite bounded evidence remain outside the architecture's authority.
