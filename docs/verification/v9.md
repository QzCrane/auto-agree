# Auto Agree v9.0.0 — Verification Report

Generated: 2026-08-08

## Scope

v9 is an invariant-recovery release derived by reconciling the complete v1→v8 engineering record against the live v8 runtime. The audit found both ordinary runtime regressions and a previously unmodeled Manifest V3 update property: an old extension isolated world can remain observable **and executable** after the new extension generation has installed into the same, non-reloaded page.

v9 therefore hardens two different boundaries:

1. current-generation correctness: one-shot unknown controls, tri-state refusal, seed ownership, dependency-safe initialization and sender-bound profile identity;
2. cross-generation click authority: a high-priority handover firewall that prevents a stale Engine world from performing agreement clicks under superseded semantics.

## Recovered current-generation invariants

- UNKNOWN-state classless controls are one-shot for the lifetime of the unresolved DOM element; cooldown expiry alone can never authorize a second toggle. If `HTMLElement.click()` itself throws before an action is dispatched, the one-shot is not consumed.
- Native `indeterminate`, `aria-checked="mixed"`, and data `indeterminate` / `mixed` states are tri-state or aggregate ambiguity and are not auto-confirmable.
- Gate→Engine seed handoff is consumed from the global exactly once but remains weakly readable by both Shadow bootstrap and scoped Engine bootstrap.
- Gate/Engine sentinels are published only after their dependencies are valid, so a partial or out-of-order injection cannot permanently poison later retries.
- Engine activation injects the current `semantic-core.js`, `risk-core.js`, and `engine.js` dependency closure. Shared semantic/risk globals may refresh across extension versions while already-running closures retain the objects they captured.
- Profile storage origin is derived from Chrome `MessageSender.origin` / `url`; content-provided origin text is neither sent nor trusted. Profile operations fail closed when no usable HTTP(S) sender origin exists.

## Cross-generation handover firewall

### Why it exists

The first expanded v8→v9 update test disproved the assumption that an already-active v8 Engine would remain the only Engine world after update. Chrome preserved the non-reloaded page and exposed both v8 and v9 isolated-world Engine sentinels.

A stronger discriminator then proved the old world was not merely a stale global: inserting `aria-checked="mixed"` after update produced **2 legacy clicks**. That exactly matches v8's old behavior—`mixed` was interpreted as explicit false, then its verifier retried once. v9 itself refuses the same tri-state control.

Therefore sentinel coexistence was a real duplicate-authority hazard, not a diagnostic artifact.

### Mechanism

On extension update, Worker rehydration now injects `handover-guard.js` **before** `bootstrap.js` into every accessible existing frame at elevated scheduler priority.

The guard:

- ignores trusted user clicks;
- observes only synthetic/untrusted clicks;
- bounds all local semantic inspection by node and character budgets;
- recognizes agreement-like click surfaces, including ordinary controls, classless local legal rows, and accessible open/closed Shadow text reachable through the extension API;
- blocks an agreement-like synthetic click unless the current Engine has synchronously issued a one-shot authorization for that exact DOM target/ancestor chain.

Current v9 Engine authorizes both first-attempt and verifier-retry `.click()` calls immediately before dispatch. A stale v8 Engine cannot access the new isolated world's WeakSet authorization state, so its synthetic agreement clicks are vetoed at capture phase. Trusted user clicks are never subject to this authorization path.

This avoids forcing all open tabs to reload and avoids synthesizing fake `freeze`, `pagehide`, or other lifecycle events into arbitrary web applications.

## Regression gates

### Tri-state refusal

Real unpacked Chrome covers three independent ambiguous-state representations in the same routine login context:

- ARIA `aria-checked="mixed"`;
- custom `data-state="indeterminate"`;
- native checkbox `indeterminate === true`.

All three must remain untouched with an exact click count of zero.

### UNKNOWN one-shot

A classless visual control with no observable checked contract is allowed one activation. The fixture then waits beyond the normal 2.2-second click cooldown, changes its legal text to trigger fresh semantic work, and requires the click count to remain exactly one.

### Cross-version update

The v8→v9 real-browser update gate keeps two already-open pages alive across the same unpacked-extension replacement:

1. **dormant v8 Probe page** — no Engine exists before update; the v9 handover guard is physically observed, then new evidence causes the old Probe path to hand through the v9 Worker into a v9 Engine;
2. **already-active v8 Engine page** — v8 Engine is proven active before update; after update both v8 and v9 Engine worlds may remain observable. The guard must nevertheless permit exactly one current-authorized routine agreement click and must reduce the legacy mixed-state discriminator from the pre-fix 2 clicks to exactly 0.

Both pages carry main-world markers that survive the extension update, proving the pages themselves were not reloaded.

### Worker identity and update contracts

Deterministic contracts prove that:

- a spoofed `message.origin` cannot redirect a profile write away from the Chrome-provided sender origin;
- a profile request without a usable sender origin fails closed with `missing-profile-origin`;
- Engine activation injects `semantic-core.js`, `risk-core.js`, and `engine.js` as one current-version dependency closure;
- update rehydration injects `handover-guard.js` before `bootstrap.js` across all frames;
- current Engine source contains the handover authorization path;
- production source remains free of network clients, eval/dynamic Function, polling intervals, debugger use, and whole-page `querySelectorAll('*')` scans.

## Adversarial discovery history

## Remaining evidence boundary

The v8→v9 handover cannot be made mathematically atomic without cooperation from v8 or forcing a page navigation/reload: there is a finite interval between extension replacement and the v9 Worker's successful guard injection into a surviving frame. v8 did not ship a resident generation lease that v9 could revoke synchronously. v9 therefore uses high-priority resumable guard injection and proves post-install guard behavior in real Chrome, but it does not claim a zero-time transition window.

The firewall is intentionally scoped to untrusted agreement-like clicks. It is not a generic sandbox for every possible side effect that arbitrary historical extension code could perform. This is appropriate for Auto Agree's actual old Engine authority, whose consequential action is clicking a consent control.

Finally, the regression corpus is still structural rather than internet-exhaustive. Current hard browser boundaries such as Chrome-owned UI, controls requiring trusted physical input, and pure Canvas/WebGL interaction without a usable DOM/accessibility surface remain outside this architecture's authority.
