# v11.0.0 verification report

## Release scope

v11.0.0 is the formal release cut after the pre-v11 correctness-convergence program. The runtime generation moves coherently from `10.0.0` to `11.0.0`; this is not a feature-accumulation release. Its primary purpose is to turn previously discovered safety, bounded-work, lifecycle and cross-generation invariants into one release baseline with durable machine gates.

The release preserves the product invariant:

> minimize routine access friction only when live evidence still classifies the action as routine; meaningful legal, financial, factual, optional or attestation consent must remain user-owned.

## Generation coherence

The production generation has **10 version surfaces**:

- `bootstrap.js` Probe sentinel;
- `gate.js`;
- `generation-lease.js`;
- `semantic-core.js`;
- `risk-core.js`;
- `handover-guard.js`;
- `engine.js`;
- `worker.js`;
- `extension/manifest.json`;
- `package.json`.

The release migration was fail-closed. It initially exposed two governance mistakes rather than silently producing a mixed generation: Worker was a real version surface that the first census had omitted, and several tests treated `10.0.0` as a permanent constant. No partial v11 product commit was accepted while those assumptions remained.

`tests/version-contract.mjs` is now the generation authority. It requires:

- manifest and package versions to match;
- exactly one runtime generation sentinel in each of the eight production JavaScript modules;
- every sentinel to equal the manifest generation;
- the production JavaScript closure to be exactly the eight expected modules;
- no second/foreign semantic-version generation literal in production JavaScript.

Current-generation tests no longer encode `10.0.0`; they derive the candidate generation from the manifest. This includes the basic unpacked E2E, generation-lease unit model, Worker contract/profile governance and Worker restart/update-rehydration model.

## Safety semantics

### Multilingual routine/risk parity

Before the formal release cut, the semantic/risk language boundary was audited and repaired. A language family that can grant routine Terms/Privacy assent recognition must also carry native-language fail-closed evidence for representative optional and high-consequence consent.

The deterministic consent model now exercises 10,188 assertions, including financial, loan, investment, insurance, medical, biometric, employment/rights, arbitration, subscription/renewal and factual/age-attestation evidence. Localized risk evidence may raise severity and suppress automation; it cannot create click authority.

`tests/property-semantic-fragmentation.mjs` adds 644 deterministic fragmentation assertions. Routine and blocking semantics therefore retain their intended classification when framework markup splits text across DOM fragments.

### Structural real-browser corpus

The permanent fixed-seed Chrome corpus contains 300 dynamic agreement contexts spanning native/external labels, ARIA IDREFs, custom controls, wrapper depth, text fragmentation and multilingual semantics. The release gate requires:

- false positives = 0;
- false negatives = 0;
- duplicate toggles = 0.

The release candidate passed all 300 cases.

## Lossless bounded discovery

v11 formalizes the rule introduced by ADR 0012:

```text
hard representation cap != permission to forget live semantic work
```

The following resource bounds remain hard; none were increased to make the tests pass.

### Probe and Gate

- Probe `MAX_DEEP = 4`: excess live final state remains weakly recoverable.
- Gate `MAX_BATCH_JOBS = 6`: evicted live batch ownership re-enters bounded deep discovery.
- Gate `MAX_DEEP_JOBS = 10`: existing FIFO cursors outrank new excess work; excess live roots are weakly coalesced.
- Gate `JOB_TTL_MS = 2400`: age alone cannot retire connected live work.
- A zero-budget Gate deep slice does not mark a job started until it actually processes its first node.

The Gate-deep saturation case runs on five independent pages in every canonical Chrome run. A dedicated live-TTL test blocks the renderer for about 2.7 seconds and still requires exactly-one eventual activation.

### Engine RootBatch

`MAX_ROOT_BATCHES = 8` remains hard. Overflow coalesces final live DOM state instead of naked oldest-batch deletion. `ROOT_BATCH_TTL_MS = 3000` is also unchanged: a live batch that merely waited beyond the age threshold refreshes liveness age and continues from its existing `index`.

A real Chrome discriminator uses 60 connected roots × 420 descendants with the unique target in root 42 and a ~3.4-second renderer stall.

### Engine walk jobs

`MAX_WALK_JOBS = 12` remains hard. Existing FIFO cursors stay authoritative; only a new excess root is weakly coalesced into `walkRecoveryRef` and promoted after ordinary RootBatch/walk work drains.

The permanent Chrome discriminator uses 20 roots × 900 nodes and a fixed 9-second eventual-progress deadline.

### Engine mutation/sibling batches

`MAX_BATCH_JOBS = 8` and `BATCH_JOB_TTL_MS = 3000` remain unchanged. A connected sibling-range owner cannot be retired by age alone; the job continues its existing `currentRef` / `subjob` / `reachedLast` state.

The permanent browser discriminator appends one MutationRecord containing 140 siblings, places the only routine target at sibling 70 outside the edge-sampling paths, and blocks the renderer for ~3.4 seconds.

### Broad closed-Shadow discovery

`MAX_SHADOW_JOBS = 8` remains hard. Historical oldest-job eviction was proven to lose unique closed-Shadow evidence. Existing FIFO cursors now remain authoritative; only a new excess root is weakly coalesced into `shadowRecoveryRef`, and recovery is promoted after RootBatch, walk, mutation-batch and ordinary shadow work drain.

The permanent test uses 14 roots × 900 nodes. The unique target is inside a closed ShadowRoot on a plain `DIV`, so ordinary `probeShadow(host, false)` cannot accidentally rescue the case; only broad closed-Shadow discovery can reach it.

All recovery state is lifecycle-owned, uses weak DOM ownership, and is cleared on retirement. No recovery path introduces an unbounded synchronous full-document scan.

## Click authority and generation safety

### Cooperative generation lease

Every Probe/Gate/Engine-capable isolated world carries the cooperative generation lease. The release candidate's future-generation probe physically replaced the same unpacked path with a manifest-only next major while keeping the page alive.

Run `31586515516` produced:

```text
fromVersion:          11.0.0
probeVersion:         12.0.0
pageReloaded:         false
oldEngine:            11.0.0
oldLease:             11.0.0
staleLeaseCurrent:    false
staleAutomatedClicks: 0
directStaleClicks:    0
trustedClicks:        1
```

This demonstrates that an observable old JavaScript execution context is not equivalent to retained extension action authority.

### Historical handover firewall and causal delegation

The handover guard remains the compatibility firewall for historical worlds that did not ship a cooperative lease. It consumes shared bounded semantics and restricts local delegation to one exact delegated control bound to one exact live source `Event`.

Stopped propagation cannot preserve authority into a later task because the source event itself must still be in browser dispatch (`eventPhase != NONE`). Broad page/form containers, proceed actions and ambiguous multi-control wrappers cannot mint sibling-control authority.

### Rejected authorization discriminator

A separate real-browser discriminator replaced only the public guard API object with `authorize() => false` while leaving the original guard closure/capture listeners installed. Engine actually attempted authorization twice (initial attempt plus bounded retry), yet automation produced:

```text
checked: false
clicks:  0
```

A subsequent trusted browser click produced exactly one click. Therefore the existing event boundary is demonstrably fail-closed even though Engine does not branch on the public `authorize()` return value; v11 does not add a redundant speculative runtime condition.

## Worker/profile governance

The v5-v10 learning governance remains unchanged as a release invariant:

- 256 persistent origins maximum;
- 8 flows per origin;
- 180-day profile TTL;
- 32-entry hot LRU;
- `storage.session` + `storage.local` layers;
- flow identity = fingerprint + exact locator;
- serialized writes;
- persistence failures propagate rather than being reported as success.

Worker restart/update rehydration tests now derive the current generation from the manifest while retaining the same authority ordering: `generation-lease.js` + `semantic-core.js` + `handover-guard.js` must succeed before `bootstrap.js`; failed protection is retried and cannot be bypassed by Probe startup.

## Packaging

The deterministic package derives its executable JavaScript set from the complete production `extension/*.js` closure. `python tools/package_extension.py --check` passed on the v11 candidate, so the ZIP/runtime closure cannot silently omit a newly referenced production module while claiming integrity success.

Permissions remain unchanged: `scripting`, `storage`, `<all_urls>`. There is no debugger permission, telemetry/network client, remote code, polling loop or wildcard whole-page scan added by v11.
