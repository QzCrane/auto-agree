# v12.1.0 verification contract

v12.1 closes five gaps that remained after the v12 architecture release without widening Auto Agree's consent or permission boundary.

## Product changes

- Worker update recovery persists the exact unresolved tab set. A replacement MV3 Worker consumes that set without querying and reinjecting every already-completed tab. Permanently inaccessible browser/internal pages are terminal; transient failures remain durable.
- Engine candidate-index saturation uses a weak per-context recovery epoch. Overflow schedules one bounded root recovery for the current semantic epoch, converges before the walk begins, and may re-arm only after a later context epoch.
- The new real-Chrome saturation discriminator places the only actionable live candidate beyond the 96-entry index cap, changes credential causality after initial discovery, requires exactly one action, and pressures repeated same-epoch focus/proceed signals under a TaskDuration ceiling.

## Package identity

`release/package-manifest.json` is the sole current package authority:

```text
version=12.1.0
archive=AutoAgree-v12.1.0.zip
compression=stored
sha256=2e9b53c255d570f33b3515677d2d45bd30f35a8b093eb677d258c619f1a8d82d
textEncoding=utf-8
textLineEndings=lf
entryCreatorSystem=unix
```

The packager derives the complete `extension/*.js` closure, canonicalizes each declared text member to UTF-8/LF, emits deterministic stored entries with fixed timestamp/mode, and rejects any authority mismatch. A separate deterministic gate invokes two Python package processes in independent temporary outputs and requires byte equality and the manifest hash. Hosted Ubuntu found the former CRLF/LF checkout drift; schema v2 makes those physical rules part of the sole package authority. The v12.0.0 `1cee531a…` archive remains historical evidence only.

## Performance authority

The old single-candidate seven-run profile did not establish whether a candidate regressed relative to its exact base. The current harness checks out the exact base, alternates base/candidate execution, and samples five real-unpacked workloads: positive-tail login, negative idle, benign mutation churn, hidden-page quiescence and an eight-tab scheduler burst. Raw samples, environment identity, medians, p90s, relative limits and absolute ceilings are preserved in `artifacts/e2e-performance-paired.json`.

## Exact-head closure

`release/closeout-policy.json` defines 19 lanes and two required same-head attempts. `tools/closeout-evidence.mjs` records and verifies:

- exact base commit/tree and candidate commit/tree;
- clean tracked worktree;
- policy and package-manifest SHA-256;
- Node, Python, Chrome and Puppeteer identity plus browser mode;
- every exact command, exit code, duration and output digest;
- paired-performance artifact digest;
- hosted status as a separate enum with an explicit source, so runner unavailability cannot be rewritten as either product failure or hosted success.

Merge mode first validates both local receipts, then reads the live PR head and uses the same SHA as GitHub's expected-head compare-and-swap. It reads back the merged PR, remote-main commit, candidate/merge tree parity and remote head-ref absence without asking `gh` to switch the local worktree. The ignored receipts and PR metadata carry final exact-SHA run output; embedding a generated final SHA in this tracked report would itself create a different unverified candidate.

## Boundary

Permissions remain `scripting`, `storage` and `<all_urls>` host access. The release adds no network client, telemetry, remote code, debugger authority or broader automated-action semantics. Ubuntu/Windows are possible verification hosts, not product runtime requirements; product proof is the installed Chrome extension behavior and the declared execution environment.
