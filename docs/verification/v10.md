# Auto Agree v10.0.0 — Verification Report

Generated: 2026-08-09

## Scope

v10 continues from v9's real-browser discovery that multiple extension generations can remain JavaScript-executable in one non-reloaded page. v9 established a **new-generation handover firewall** for historical non-cooperative Engines. v10 asks a different question: can a generation that cooperates in advance revoke **its own** future Auto Agree action authority immediately when Chrome replaces the extension?

The answer in the tested Chrome lifecycle is yes for Auto Agree's ordinary `HTMLElement.prototype.click()` activation primitive. v10 adds a realm-local generation lease, keeps the v9 firewall for historical compatibility/defense-in-depth, converges firewall semantics on the shared bounded semantic core, tightens causal delegation, restores historical profile-governance contracts after adversarial review, and repairs a later-discovered deterministic packaging-closure defect.

## Evidence taxonomy

This report distinguishes four evidence classes:

1. **production invariant** — enforced by current runtime code plus deterministic contract tests;
2. **real-browser observation** — observed in a real unpacked extension in Chrome for Testing;
3. **adversarial candidate failure** — a proposed implementation that was rejected before merge;
4. **remaining boundary** — not claimed solved by v10.

## Cooperative generation lease

### Real-browser premise

A research-only real Chrome probe first activated an existing v9 Engine world, replaced the same unpacked path with a manifest-only 10.0.0 generation, and re-evaluated the **same old execution context** without reloading the page.

Before replacement, the old world reported its normal extension Runtime version. After replacement, the JavaScript context was still CDP-evaluable but `chrome.runtime` access failed with:

```text
Extension context invalidated.
```

This proves a distinction that version sentinels alone cannot express:

```text
old JavaScript context still exists
!=
old extension Runtime still owns current authority
```

The exploratory PR carrying only this probe was intentionally not a release candidate. Its other version-transition step was obsolete for the new PR base, but the generation-runtime observation itself completed before that unrelated failure.

### Production mechanism

`generation-lease.js` is now installed before Probe and included in every dynamic Gate/Engine/update-protection dependency closure.

Inside Auto Agree's isolated world it wraps that realm's `HTMLElement.prototype.click`. Before dispatching, the wrapper checks:

```text
chrome.runtime.getManifest().version === compiled generation
```

A generation mismatch or an invalidated extension context returns without dispatching the DOM click.

The wrapper is not installed into the page MAIN world and does not add a global event listener.

## Why the v9 handover firewall remains

The cooperative lease cannot retroactively modify v9. Therefore v9→v10 still uses the new generation to establish protection before Probe rehydration.

v10 update protection is ordered as:

```text
generation-lease.js
+ semantic-core.js
+ handover-guard.js
        ↓ protection resolves
bootstrap.js
```

If protection fails for a tab, protection is retried and `bootstrap.js` is not intentionally started for that tab.

The normal Engine dependency closure is:

```text
generation-lease.js
semantic-core.js
handover-guard.js
risk-core.js
engine.js
```

This guarantees that a page created through update rehydration—not only a freshly navigated page—carries the cooperative lease before it can become an Engine world.

## Handover semantic convergence

v9's firewall initially contained a smaller private legal/assent/required vocabulary. That created a semantic-drift risk: current Engine could understand a consent surface that the firewall did not recognize as agreement-like.

v10 removes the private vocabulary. `handover-guard.js` consumes the same `semantic-core.js` used by Gate/Engine and uses its bounded normalization and `assessText(...)` authority.

Additional bounded relation resolution includes:

- `aria-labelledby`;
- `aria-describedby`;
- native `HTMLInputElement.labels` / external `<label for>` relationships;
- local Shadow text through the extension API path.

The guard also restores the v6 pathological-string invariant: raw values are bounded/sampled by the shared normalizer **before** regex normalization. It no longer performs `String(value).replace(...).slice(...)` over an arbitrarily large raw attribute/text value.

## Causal delegation hardening

A second v9 weakness was discovered in trusted-event causal delegation. A generic ancestor could use `querySelector(CONTROL)` over an unbounded subtree, which had two independent problems:

1. hot-path work was not structurally bounded;
2. a user click on an unrelated action in a broad wrapper could find and authorize a distant sibling Terms control.

v10 replaces that search with a hard-bounded local-wrapper walk:

```text
max wrapper depth:  2
max control depth:  3
max visited nodes: 64
```

The delegated target must be unique. Ambiguous wrappers with multiple candidate controls fail closed. Broad `html/body/form/dialog/main/section/article/aside/nav/header/footer` containers are excluded. Proceed/action targets cannot mint sibling-control authority. Native label delegation uses the exact associated `label.control` when available.

No timer-backed causal authorization exists; capture grants the exact same-event local lease and bubble revokes it.

## Site-learning governance re-audit

During v10 development, a handover-focused Worker rewrite reached green handover CI while silently changing unrelated established learning/storage properties. Adversarial review rejected that candidate before release.

The rejected rewrite would have changed or removed several v5–v9 contracts, including origin/flow bounds, TTL, session caching, exact flow identity and storage-error semantics. This demonstrated a key testing lesson:

```text
handover tests green
!=
repository-wide invariants preserved
```

v10 therefore restores the v9 Worker as the trust root and layers only the required v10 update mechanics on top.

New `worker-profile-governance.mjs` regressions prove:

### 64 concurrent flow writes — PASS

One origin receives 64 concurrent profile writes. The Worker serializes mutation and retains the newest **8** verified flows.

### Same fingerprint, distinct locator identity — PASS

Two flows may share a context fingerprint while having distinct verified locators. Both survive; precise invalidation of one locator leaves the sibling locator intact.

### 300-origin cap — PASS

Persistent profile/index state converges to at most **256 origins** and evicted origins lose their persistent profile objects.

### Persistence error propagation — PASS

A synthetic `storage.local.set` failure causes profile PUT to return `ok:false`. Persistence failure is not swallowed and reported as success.

The retained canonical policy is:

```text
worker hot LRU:       32 entries
persistent origins:  <=256
flows/origin:        <=8
TTL:                  180 days
hot session layer:    chrome.storage.session
persistent layer:     chrome.storage.local
flow identity:        fingerprint + exact locator
```

Cache remains discovery acceleration only; live semantic/risk authority is always re-evaluated.

## Package dependency closure — repaired

v10 audit found a real release-engineering defect in the previous deterministic packager: it maintained a second hand-written JavaScript file list. New runtime modules could be present in the canonical `extension/` tree and exercised by load-unpacked E2E while being absent from the generated ZIP.

In particular, the inherited list did not include the generation handover module added after the original list was established. ZIP integrity could therefore pass while the runtime closure was incomplete.

v10 changes the packager to derive its JavaScript payload from the complete production `extension/*.js` set plus `manifest.json` and runtime `README.md`.

`python tools/package_extension.py --check`: **PASS** in run **31271766243**.

This is recorded as a **later-discovered packaging limitation of the older gate**, not as a retroactive claim that v9's load-unpacked Chrome behavior tests did not run; those tests loaded the canonical `extension/` directory directly.

## Remaining boundaries

### Historical non-cooperative transition

v9→v10 still needs the new-generation firewall because v9 never shipped the cooperative lease. v10 cannot retroactively remove the finite pre-guard interval from a generation that did not know how to self-revoke.

### Lease scope

The cooperative lease revokes Auto Agree's isolated-world `HTMLElement.prototype.click()` primitive. It is not a generic sandbox for arbitrary stale JavaScript side effects or a formal proof about every possible future activation primitive. The handover guard remains defense-in-depth for agreement-like synthetic event authority.

### Browser lifecycle premise

The lease depends on behavior observed in real Chrome: old extension Runtime becomes invalid/current-version mismatched across replacement while the old JS context may persist. That is why the real  current→next manifest-generation probe is permanent CI rather than a one-time experiment.

### Web surface boundaries

Chrome-owned UI, sites that require trusted physical input, pure Canvas/WebGL interaction with no usable DOM/accessibility surface, and a completely signal-free closed ShadowRoot before any relevant user interaction remain outside the guaranteed authority of this content-script architecture.

### Internet-scale precision

The real and fuzz corpora are regression evidence, not proof of zero false positives/false negatives across arbitrary future websites. New real-world misses or false positives must continue to be minimized, sanitized and added to `tests/fixtures/regressions/`.
