# Auto Agree v2.0.0 — Reconstructed Historical Record

> Evidence class: **reconstructed from the original v2 commit** `83056273c98566321606dc706f4d8ec733312e84`.
>
> Unlike v1/v1.1, the v2 commit itself already included a concise architecture/coverage/performance note. This file expands that committed record and distinguishes committed design from limitations discovered later. No unrecorded benchmark numbers are invented.

## 1. v2 design target

v2 was the first deliberate performance/coverage refactor rather than a local patch.

The committed design goals were:

1. high precision — accept mandatory Terms/Privacy, not generic checkboxes;
2. broad coverage — native, ARIA, framework/Web Component, iframe, open/closed Shadow DOM;
3. low overhead — one shared observer, incremental subtree walks, no repeated whole-document fallback, geometry only for high-confidence classless fallbacks;
4. idempotence — never blindly click twice when state is not observable.

## 2. Explicit bounded runtime constants

v2 introduced hard operational budgets rather than allowing every scan to expand with page size:

- `WALK_SYNC_BUDGET = 900`;
- `WALK_IDLE_BUDGET = 3500`;
- bounded context/row text sizes;
- bounded pending-visibility set;
- per-target click cooldown.

These were early forms of the later time-budget, queue-cap, WeakRef, and lifecycle-generation invariants.

## 3. Semantic model split into independent evidence classes

v1/v1.1 primarily used a weighted positive list.

v2 separated semantic dimensions:

- `LEGAL` — Terms/User Agreement/Privacy/License vocabulary;
- `ASSENT` — agree/accept/read-and-agree language;
- `READ_WORD` — acknowledgement/read evidence;
- `REQUIRED` — mandatory wording;
- `VALIDATION` — “please agree before continuing” style evidence;
- `AUTH` — login/register/phone/OTP context;
- `PROCEED` — login/continue/submit/verify actions;
- `NEGATIVE` — optional/unsafe controls;
- `ATTESTATION` — age/identity/factual declarations.

This was a major move away from “one score over one text blob” toward evidence composition.

## 4. Multilingual expansion

v2 substantially expanded legal, assent and authentication vocabularies across:

- Simplified/Traditional Chinese;
- English;
- French;
- German;
- Spanish;
- Portuguese;
- Italian;
- Japanese;
- Korean;
- Russian;
- Arabic;

The purpose was not translation completeness by itself; it was to maintain the same semantic decomposition—legal + assent + context—across scripts/languages.

## 5. Stronger safety boundary

v2 explicitly separated factual attestations from routine access consent.

Examples included age/legal-age, identity/real-name and “I certify/confirm/declare” patterns.

This established a durable rule later generalized by the consent-severity lattice:

> A checkbox that asserts a fact about the user is not equivalent to a Terms prerequisite, even if the same row also links Terms.

The negative set also retained exclusions for marketing, cookies, remember-me, auto-renewal, CAPTCHA and optional sharing/personalization.

## 6. Control coverage

v2 broadened direct control handling to:

- native checkbox;
- agreement radio controls;
- ARIA checkbox/radio/switch;
- common Web Component/framework checkbox wrappers;
- custom elements with checkbox-like tags/classes;
- classless visual checkbox fallback after strong legal evidence.

This is the point where checkbox-specific logic became a more general **consent-control state machine**.

## 7. Open and closed Shadow DOM

v2 introduced the extension-specific closed-root path using `chrome.dom.openOrClosedShadowRoot()` where available.

That was a qualitative improvement over v1/v1.1’s open-root discovery via `element.shadowRoot`.

A single MutationObserver instance could observe the document plus discovered ShadowRoots rather than creating a completely separate scanning architecture per root.

## 8. Frame coverage

The v2 manifest expanded related-frame handling beyond basic `all_frames`/`about:blank` semantics to include origin-fallback coverage for related `about:`, `data:`, `blob:` and `filesystem:` contexts.

This addressed login components rendered in derived/embedded frames rather than only the top document.

## 9. Incremental DOM processing

This was the core performance change.

Instead of repeated full-page rescans, v2 moved toward:

```text
MutationObserver
    ↓
collect changed/added roots
    ↓
deduplicate descendants covered by an ancestor
    ↓
walk only dirty subtrees
    ↓
process bounded synchronous slice
    ↓
move remaining work to idle/background slice
```

The commit explicitly documented:

- one MutationObserver across document/ShadowRoots;
- incremental subtree walking;
- ancestor deduplication inside mutation batches;
- bounded synchronous work;
- `requestIdleCallback` for the remainder;
- no global class/style mutation observation.

This removed the v1-era pattern where a login preflight or DOM change could easily trigger another broad whole-document pass.

## 10. Layout/geometry isolation

v2 deliberately separated reliable semantic controls from classless visual fallbacks.

For native/ARIA/known-component paths, geometry was not supposed to be the primary decision mechanism.

Geometry/layout work was reserved for the hard case:

```text
strong legal/assent evidence
+
no useful checkbox semantics
→ visual target fallback
```

That direction later became even stricter after pressure tests demonstrated how a geometry read immediately after a huge DOM insertion can force expensive style/layout work.

## 11. Hidden-to-visible recovery

v2 introduced bounded tracking for controls that had already been semantically identified but were not currently visible.

`ResizeObserver` was used to revisit them when layout made them visible, rather than continuously polling the page.

This improved animated/delayed login dialogs while preserving the no-interval design.

## 12. Unknown-state one-shot policy

The v1.1 safety rule was retained and formalized:

- if state is observable, verify and allow a bounded retry when it is definitely still unchecked;
- if custom state is unknown, do not blindly toggle a second time.

This became a permanent invariant in later versions.

## 13. v2 architectural strengths relative to v1.1

The main improvements were therefore not merely “more sites”:

- evidence dimensions became explicit;
- attestation became a first-class exclusion;
- consent controls expanded beyond checkbox;
- closed Shadow DOM gained an extension-native path;
- frame coverage widened;
- scans became dirty-subtree incremental work;
- synchronous work acquired budgets;
- idle scheduling moved expensive remainder off the mutation hot path;
- geometry became a late fallback;
- hidden controls used event-driven recovery;
- retry/idempotence became state-aware.

## 14. Limitations later exposed

These are retrospective and are not presented as v2 release-time measurements.

### 14.1 Full engine still lived in every matching frame

Even though its internal work was much better bounded, the complete engine still existed on every page/frame. v3 later moved to lazy frame-specific injection.

### 14.2 Node-count budgets were not true time budgets

`900` easy nodes and `900` expensive candidate/Web Component nodes can have very different CPU cost. Later versions migrated scheduling toward elapsed-time budgets and `scheduler.yield/postTask`.

### 14.3 Candidate text could still allocate a large subtree string before truncation

The v2 code reduced use of `innerText`, but some candidate paths still obtained `textContent` and only then sliced it. Later versions replaced this with genuinely bounded text walkers and eventually fixed pathological single multi-megabyte attribute/TextNode values too.

### 14.4 Strong references in pending queues

Some early queue/visibility structures used strong `Set<Element>`/walker ownership. v5 later demonstrated that frozen/background scheduling can turn those into detached-DOM retention and replaced them with weak ownership.

### 14.5 TreeWalker across scheduling boundaries

The v2 incremental walker architecture was a major CPU improvement, but later memory attacks showed that retaining a TreeWalker across a yield can itself keep a detached root alive. v5 replaced cross-yield TreeWalkers with weak root/cursor traversal.

### 14.6 Risk semantics were still mostly rule buckets, not ordered consequence severity

v2 knew that attestation and many optional actions were different, but it did not yet have v7’s monotonic `ROUTINE → PRIVACY → OPTIONAL → CONSEQUENTIAL → ATTESTATION` decision lattice.

## 15. Historical significance

v2 is the point where Auto Agree stopped being primarily a script with heuristics and became an explicit **bounded reactive engine**.

The durable ideas introduced here include:

- bounded work;
- dirty-subtree processing;
- semantic evidence decomposition;
- factual-attestation exclusion;
- closed Shadow support;
- event-driven visibility recovery;
- control-state idempotence;
- geometry only as a high-confidence fallback.

v3–v7 mostly refine these principles at larger system scale.
