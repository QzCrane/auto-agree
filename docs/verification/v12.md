# v12.0.0 verification report

## Scope

v12 is the architecture/governance convergence release. It does not broaden the product's consent boundary or permissions. It makes previously distributed authorities explicit, removes duplicate policy/mechanism implementations, makes test registration self-maintaining, upgrades performance evidence from single snapshots to repeated distributions, and proves the physical 11.0.0 → 12.0.0 update.

This report records the **physical release candidate** that carried only the four version-generation edits. The final documentation-complete release PR reuses those exact four blobs and re-runs the same current gates; exact final-head CI IDs remain authoritative in that PR/merge metadata so embedding them here does not create another unverified SHA.

## Architectural authority convergence

### RuntimeKernel / lifecycle / bounded work

Probe, Gate and Engine now share RuntimeKernel lifecycle epochs and bounded FIFO/live-age primitives while retaining tier-specific observers/queues/budgets. Real Chrome gates preserve the historical hard caps and final-state/lifetime invariants:

- Probe/Gate saturation with weak/FIFO recovery;
- Probe/Gate live work beyond their age thresholds;
- Engine walk saturation (`MAX_WALK_JOBS=12`);
- Engine RootBatch live work beyond `ROOT_BATCH_TTL_MS=3000`;
- Engine >96-node sibling range with 140 siblings and target at sibling 70 beyond `BATCH_JOB_TTL_MS=3000`;
- broad closed-Shadow pressure with `MAX_SHADOW_JOBS=8` and a unique target inside a closed ShadowRoot on a plain host.

No v12 repair raises those caps or replaces them with an unbounded whole-page scan.

### DecisionKernel

DecisionKernel is now the sole severity lattice and acceptance policy. Engine maps browser evidence to EvidenceIR; Risk Core consumes DecisionKernel severity; ProfileCore receives any needed policy threshold rather than defining another domain lattice.

A dead duplicate `SEVERITY` object in Semantic Core was removed by #49 and static/property contracts forbid another duplicate policy owner.

Classless geometry also crosses DecisionKernel and has a separate 6,000-case property discriminator plus real-Chrome routine/risk test.

### SchedulerCore

Worker scheduling policy was extracted to pure SchedulerCore with 12,500 differential/property cases. Worker retains Chrome side effects/queue execution; global/per-tab caps, aging, stale semantics, tie fairness and preemption selection have one policy owner.

### ProfileCore

Profile schema/merge/identity/compatibility/resource bounds converged on ProfileCore. Current governance remains:

- 256 persistent origins;
- 8 flows/origin;
- 180-day TTL;
- 32-entry Worker hot LRU;
- session + local storage;
- exact fingerprint + validated locator identity;
- finite/bounded counters/timestamps/descriptors;
- future-dated acceleration evidence fails closed;
- serialized persistence with errors remaining failures.

Profiles remain acceleration only; live browser evidence + Risk/Decision policy + ActionAuthority are still required.

### DomCore

Engine and Handover Guard had duplicate composed-parent / root-scoped IDREF logic. v12 removed those private copies and introduced a tiny DomCore owning only those two topology primitives. Static contract forbids DomCore from growing TreeWalker/textContent/full-scan policy. Gate/Guard/Engine text scanners remain tier-local because their cost/security budgets differ.

### ActionAuthority

Engine's two automated action sites previously repeated `authorize -> click` logic. v12 centralizes them behind the 31-line ActionAuthority protocol:

```text
HTMLElement
→ current matching Generation Lease
→ current matching Handover Guard authorization
→ one target.click() attempt
```

Generation Lease and Handover Guard remain independent mechanisms; ActionAuthority does not absorb their state machines. Engine's live verifier remains the sole DOM-success observer.

## Three-layer action authority in real Chrome

Canonical/rerun literal:

```text
e2e-authorize-rejection: {
  "attempts":1,
  "engineBlocked":{"checked":false,"clicks":0},
  "syntheticCalls":1,
  "guardBlocked":{"checked":false,"clicks":0},
  "trusted":{"checked":true,"clicks":1}
}
```

The cumulative `syntheticCalls=1` is produced by a **separate direct-synthetic probe** after Engine rejection. The test explicitly asserts the primitive count is 0 immediately after ActionAuthority receives `authorize=false`.

Interpretation:

1. ActionAuthority rejection prevents Engine from dispatching any synthetic click.
2. A separately forced current-generation isolated `.click()` does reach the primitive, but Handover Guard independently cancels the unauthorized agreement DOM effect.
3. Trusted browser input remains usable.

Thus the layers are independently discriminated rather than inferred from one final zero-click result.

### Variance limitation

The statistical protocol itself was introduced and attacked before the release cut. On identical code/browser versions, two hosted-runner executions produced materially different median regimes (~218.9 ms and ~276.8 ms). That is evidence against interpreting one CI wall-clock profile as a stable code-performance delta.

Accordingly, v12 did **not** introduce speculative runtime optimization in response to an isolated 180–300 ms sample. No stable new hotspot attributable to RuntimeKernel/DomCore/ActionAuthority/ProfileCore was demonstrated.

## Red evidence and corrected historical claim

The first pure v12 generation-cut attempt (#52) correctly failed before producing a product candidate. The production cut itself reached 12.0.0, then `npm test` failed at:

```text
tests/runtime-kernel.mjs:10
AssertionError: '12.0.0' !== '11.0.0'
```

The RuntimeKernel unit still contained `assert.equal(kernel.version, '11.0.0')`.

This falsifies the broad statement in the historical v11 report/changelog that all current-generation release-number magic had already been removed. The historical v11 report is intentionally not rewritten. v12 records the correction:

- #54 changed RuntimeKernel unit expectations to derive the manifest generation;
- `version-contract` now also covers package-lock top/root generations;
- `version-contract` machine-checks that RuntimeKernel tests cannot regress to a literal current-semver assertion;
- post-merge 11.0.0 main passed core/full Chrome/statistical performance;
- the corrected four-file cut (#55) then ran all 27 deterministic gates successfully while already at 12.0.0.

This is a concrete example of the project's evidence rule: a prior verification claim is evidence to attack, not authority to preserve.
