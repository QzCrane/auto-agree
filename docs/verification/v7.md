# Auto Agree v7.0.0 — Verification & Repository Convergence Report

Generated: 2026-08-08

## Scope

v7 combines production-runtime optimization with repository convergence. The runtime work targets semantic consistency, consent severity, render-burst coalescing, intent prewarming, behavior-aware learning, and cross-frame injection pressure. The repository work removes obsolete live files and creates durable architecture/testing/history/decision records.

## Production changes

### Shared base semantics + lazy risk core

v6 Gate and Engine maintained overlapping legal/assent rules. v7 replaces that drift risk with:

- `semantic-core.js`: bounded normalization, legal/assent/required/auth primitives shared by Gate and Engine;
- `risk-core.js`: optional/consequential/attestation semantics loaded only after Gate accepts the frame.

Worker injection order:

- Gate: `semantic-core.js` → `gate.js`;
- Engine: `risk-core.js` → `engine.js`.

The semantic base therefore exists once per activated frame, while high-risk rules are not moved into the earlier Gate tier.

### Consent severity

Binary risk becomes a monotonic lattice:

0. routine;
1. routine privacy;
2. optional/nonessential;
3. consequential;
4. attestation.

Engine activation is prohibited at level 2 or above. A consequential clause dominates routine Terms text in the same control.

### Semantic graph

Each candidate decision materializes bounded relationship facts between control, semantic row, context, legal references and proceed action. The final decision is synthesized from graph facts rather than a flat score alone.

### Mutation transaction

Detailed context mutations are coalesced per lifecycle generation. One render burst invalidates a context epoch once and re-evaluates the context's existing candidate index once, rather than repeatedly rebuilding the same context snapshot.

### Intent prewarm

Existing low-frequency events contribute intent evidence: credential focus/input, Enter, and proceed-action interaction. High intent prewarms the current context/candidate index. No mousemove/pointermove polling is added.

### Behavioral learning

Persisted flow records now include a bounded behavior descriptor (state kind, severity, legal/assent/required/auth/link strength). A locator that still resolves but no longer matches its learned behavior descriptor is negative feedback, not authority.

### Worker injection scheduler

Dynamic script injection has hard resource bounds:

- max 4 concurrent injections globally;
- max 2 concurrent injections per tab;
- Engine priority over Gate;
- queue hard cap 64.

## Repository convergence

Before v7 the live tree mixed current extension source with root-level version reports and retained the obsolete `auto-agree-extension/content.js` implementation. Commit messages were only version labels.

v7 canonical layout:

- `extension/`: only current load-unpacked production source;
- `tests/`: executable contract/property tests;
- `tools/`: deterministic packaging;
- `docs/verification/`: historical verification reports;
- `docs/decisions/`: ADRs;
- root: README, changelog, security, contributing, package/CI metadata.

`content.js` is removed from the live tree; Git history remains the archive.

## Deliberately rejected additions

### chrome.debugger Accessibility bridge

Rejected for production default. The required `debugger` permission materially expands the extension trust/warning surface and Chrome does not allow that permission to be optional. Current evidence does not justify paying that cost for all users.

### Untrained local ML classifier

Rejected pending a large independently labelled real-world consent corpus. Shipping an uncalibrated model would add opaque failure modes without evidence that it lowers false negatives while preserving the stricter consequential-consent false-positive bound.

## Static production invariants

The test suite prohibits:

- page-network `fetch`/XHR/WebSocket paths;
- `eval` / dynamic Function;
- polling `setInterval`;
- whole-page `querySelectorAll('*')`;
- `chrome.debugger` / debugger permission.

Manifest permissions remain exactly `scripting`, `storage`, and `<all_urls>` host access.

## Environment boundary

The managed environment still prevents a true unpacked-extension install against arbitrary production sites. Browser checks therefore use Chromium's real DOM/event/layout engine with extension-only APIs shimmed where required. This report does not mislabel those tests as arbitrary-site production E2E.
