# v12.2.0 verification contract

## Scope

v12.2 repairs a real coverage hole at the **Probe → Gate activation boundary** without widening the final consent/action policy.

The prior structural browser corpus was strong evidence for Engine behavior after activation, but its 300-case fuzz mounted the complex controls only after a seed had already caused Engine to exist. That meant the suite could remain green while a real page failed earlier: the always-present Probe could miss a structure and therefore never load Gate or Engine at all.

This release treats activation recall as an independent product invariant instead of inferring it from downstream Engine correctness.

## Root cause

The 12.1 Probe intentionally stayed cheap, but several independent bounded shortcuts composed into false negatives:

- ordinary legal text to control discovery used a shallow generic ancestor relation;
- direct text-node paths discarded nodes longer than 900 characters instead of using the bounded head/center/tail sampler already available in Probe;
- the MutationObserver did not watch late `aria-labelledby` / `aria-describedby` relationship changes common in SPA/component hydration;
- pointer/focus discovery stayed inside the immediate form/dialog or parent scope, so a custom non-form access shell could fail to reveal a nearby legal control even when the user explicitly pressed a proceed action.

The problem was therefore not that DecisionKernel, Engine, or ActionAuthority had lost the ability to accept a routine agreement. The richer runtime could simply fail to start.

## Repair

`bootstrap.js` now restores recall through **explicit semantic relations and bounded user intent**, not by turning broad DOM geometry into consent authority:

1. Deep native-label relationships may activate Gate through a fixed eight-ancestor search that accepts only a real `<label>` relation.
2. Long text nodes are passed through Probe's existing bounded head/center/tail normalizer before legal-text matching; multi-megabyte input remains bounded.
3. Probe observes live changes to `aria-labelledby`, `aria-describedby`, `aria-required`, `for`, and related semantic attributes so late component binding can activate richer analysis.
4. A real proceed-like interaction (`login`, `continue`, `next`, `submit`, `verify`, and supported Chinese equivalents) may search a bounded six-ancestor region with fixed node/time budgets.
5. Generic text/control geometry remains at the prior shallow bound. Deep geometry without an explicit label/ARIA relation or proceed signal is not promoted merely because legal text and a required checkbox coexist.

Gate, DecisionKernel, Risk Core, Engine, Handover Guard, and ActionAuthority are unchanged by this repair.

## Real Chrome activation discriminator

`tests/e2e-activation-recall.mjs` runs the actual unpacked MV3 extension and requires observable DOM outcomes, not just module presence.

Positive cases:

- deeply nested text and control joined by one native `<label>`;
- a legal text node beyond the former direct 900-character cutoff;
- SPA-style late `aria-labelledby` binding where text and control are otherwise geometrically remote;
- a custom non-form/non-dialog access shell that becomes locally searchable only after a trusted `Continue` interaction.

Every positive case requires the actual agreement control to become `checked=true` and requires both Gate and Engine to have been reached.

Negative case:

- geometrically remote Terms text plus a semantically neutral required checkbox, with no native-label/ARIA relation and no proceed interaction, must remain `checked=false`.

This negative is deliberately neutral (`id=generic-box`). An earlier draft used `id=agree`, which was not a valid geometry-only negative because `agree` is itself explicit semantic evidence; that test was rejected during adversarial review.

The activation discriminator is a permanent hosted unpacked-Chrome CI step and a formal exact-head closeout lane. The executable closeout policy therefore contains **20 lanes × 2 same-head attempts**.

## Generation boundary

The behavior change advances the physical runtime generation from 12.1.0 to **12.2.0** across:

- `extension/manifest.json`;
- RuntimeKernel's sole isolated-world birth-generation literal;
- `package.json`;
- package-lock top-level/root-package versions.

This is security-relevant, not cosmetic: a surviving 12.1 isolated world must become stale after 12.2 replaces the extension rather than sharing current-generation `.click()` authority with behaviorally different code.

## Release evidence policy

The final exact PR head must pass:

- all auto-discovered deterministic/core gates and TypeScript;
- deterministic package reproduction against the authority above;
- full real unpacked Chrome behavior, including the activation-recall positive/negative discriminator;
- Probe/Gate/Engine pressure and lifecycle regressions;
- ActionAuthority and cooperative stale-generation revocation;
- the exact 12.1 → 12.2 non-reloaded update transition;
- the exact-base/exact-head five-workload paired performance matrix;
- a same-SHA hosted rerun of the canonical jobs before expected-head merge.

Exact final-head workflow/job identifiers belong in PR #64 metadata because committing generated run IDs into this tracked report would move the candidate SHA and invalidate the evidence it names.

## Boundary

Permissions remain `scripting`, `storage`, and `<all_urls>` host access. v12.2 adds no network client, telemetry, remote code, debugger authority, cookie/history access, or new permission. It does not widen DecisionKernel severity/acceptance policy or ActionAuthority; it repairs whether the existing richer policy stack is reached when bounded, explicit evidence justifies inspection.
